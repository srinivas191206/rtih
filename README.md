## 📌 What Is RTIH InnovationOS?

RTIH InnovationOS is a **government-grade startup management platform** built for the [Ratan Tata Innovation Hub](https://rtih.ap.gov.in), the flagship deep-tech incubator of the Government of Andhra Pradesh.

The platform manages the **full innovation lifecycle** — from a first-time entrepreneur applying through a university cell in Kurnool, to a growth-stage startup closing a seed round from a Hyderabad investor — all within a single, role-aware operating system.

### The Problem It Solves

> Government startup programs fail not because of lack of funding, but because of lack of visibility, accountability, and real-time feedback loops between founders, mentors, and policy makers.

RTIH InnovationOS replaces fragmented spreadsheets, email threads, and WhatsApp groups with a **single source of truth** for the entire AP innovation ecosystem.

## 🔄 Real-Time Sync Architecture

The app uses a **3-layer sync strategy** ensuring zero-latency UX with strong consistency:

```
User Action
    │
    ▼
LocalStorage write  ──────────────────► Instant UI update (0ms)
    │
    ▼
Supabase upsert  ────────────────────► Cloud persistence
    │
    ▼
Supabase Realtime broadcast  ────────► All other devices/tabs update instantly
    │
    ▼
8-second polling fallback  ──────────► For environments without WebSocket support
```

## 🚀 Getting Started

### Prerequisites
- **Node.js** 18.17 or later
- **npm** (or yarn / pnpm)
- A **Supabase** project (free tier works)

### 1. Clone the repository
```bash
git clone https://github.com/srinivas191206/rtih.git
cd rtih
```

### 2. Install dependencies
```bash
npm install
```

### 3. Set up environment variables
```bash
cp .env.example .env.local
```

Open `.env.local` and fill in your values:

```env
# Required — get from Supabase → Project Settings → API
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

# Optional — AI Copilot (app works in Sandbox mode without these)
GEMINI_API_KEY=your-gemini-key
GROQ_API_KEY=your-groq-key
```

### 4. Initialize the database
Run the contents of `schema.sql` in your Supabase SQL Editor.  
The app will auto-seed demo data on the first page load.

### 5. Start the development server
```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) — click the left arrow to access demo accounts.

## 🔐 Environment Variables Reference

| Variable | Required | Exposed to Browser | Description |
|----------|----------|--------------------|-------------|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ Yes | ✅ Yes (by design) | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ Yes | ✅ Yes (by design) | Supabase public anon key — protected by Row Level Security |
| `GEMINI_API_KEY` | ⚪ Optional | 🔒 No — server only | Google Gemini API key for AI Copilot |
| `OPENROUTER_API_KEY` | ⚪ Optional | 🔒 No — server only | OpenRouter fallback AI provider |
| `GROQ_API_KEY` | ⚪ Optional | 🔒 No — server only | Groq primary AI key |
| `GROQ_API_KEYS_POOL` | ⚪ Optional | 🔒 No — server only | Comma-separated Groq key pool for rate-limit rotation |

> **Security:** `NEXT_PUBLIC_SUPABASE_ANON_KEY` is intentionally browser-visible — this is standard Supabase practice. It is protected by Row Level Security (RLS) policies, not by secrecy. All AI provider keys are server-only and never sent to the client.

## 🧠 AI Copilot — Failover Chain

The `/api/ai/copilot` endpoint tries providers in order, automatically falling back if a key is missing or rate-limited:

```
1. Google Gemini 1.5 Flash   (primary — highest quality)
        ↓ if unavailable
2. OpenRouter (Gemini 2.5)   (secondary — cloud router)
        ↓ if unavailable
3. Groq LLaMA 3.1 8B         (tertiary — key pool rotation across 10 keys)
        ↓ if unavailable
4. Sandbox Fallback Engine    (always available — curated dynamic responses)
```
